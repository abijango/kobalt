# Reader behavior

Mini Kobo test packages keep Libron, NV Bitter, interface fonts, all fallback fonts and all bundled hyphenation patterns. They have fewer recommended fonts in the font picker. Books configured with an omitted font use an available font instead. Mini packages use the same installation steps as full packages.

This document describes what Kobalt does on a device today: which builds exist, how to install and remove them, what the reader supports and what is still unverified. Build commands are in the [development guide](development.md).

## Builds and firmware

Kobalt has two Kobo builds. Each build matches the Qt version of its firmware.

| Build | Firmware | Qt | System package |
|---|---|---|---|
| `qt5` | 4.38.21908 and later 4.x | 5.2 | `KoboRoot.tgz` |
| `qt6` | 5.18 and later 5.x, and 6.x | 6.5 | `Kobo.tgz` |

The build names `nickel4` and `nickel5` still work as aliases for `qt5` and `qt6`.

The first public beta, `v1.0-beta.1`, includes only the Qt5 package. Qt6 remains a development build.

No build checks the device model or display driver. At startup, each build checks its required Nickel symbols and the registered size of Nickel's `Volume` type. The `qt5` build finds the unexported orientation singleton by its machine code and requires it to match exactly once. If a check fails, Nickel keeps its own reader. A release that keeps every symbol but changes another object size or a virtual-table slot is not detected.

## macOS testing app

The Mac app uses the same reader controls and renderer as the mobile app. Open an unprotected EPUB with the start screen, File → Open EPUB, Command-O, Finder's Open With, or by dropping one EPUB onto the window. Opening another book saves and closes the current book. The reader's Exit Kobalt button returns to the start screen.

The toolbar shows the Kobalt icon on the left, the screen picker in the center and the application version on the right. The picker selects Fill window, 6-inch e-reader or 7-inch e-reader with buttons. Fill window changes the reading viewport when you resize the window and keeps controls the same size on standard and Retina displays. Moving the window between monitors or changing the monitor DPI redraws the reader. Text reflows after the resize settles. The 6-inch preset uses a 1072 × 1448 screen and the 7-inch preset uses a 1264 × 1680 screen, both at 300 PPI. These match Clara Colour and Libra Colour screen specifications. Each device preview has a black rounded body and a black screen border, without logos. The 7-inch preview has a wider side grip with working Previous page and Next page buttons without icons. Device previews render at their native resolution and downsample once to fit the white window, without changing pagination. All modes use 300 PPI for reading settings and controls. Switching screens reflows the current book without reopening it. Device previews always show a simulated status bar with a fixed 09:00 clock and full battery. Fill window follows the saved status bar preference. Dictionaries is available in Fill window and hidden in device previews. In device previews, tap within the middle third of both the screen width and height to open or close the reading menu. These presets simulate layout and text density, not the colour filter or e-ink refresh. Left and Right, or Page Up and Page Down, turn pages while reading. Reader controls remain available through the page's touch-style controls. Mouse and trackpad clicks use the same controls: click the center of the page to show the reading menu, or the left and right sides to turn pages. Closing the window saves the reading state and waits for the engine to finish.

Settings, bookmarks, reading positions and cached layouts stay under `~/Library/Application Support/Kobalt/Kobalt/config/`. Logs go to the adjacent `diagnostics/` folder. Add personal reading fonts to the adjacent `fonts/` folder and reopen the book. Bundled fonts come from the app, so the reader does not depend on macOS font fallback.

Settings > UI appears below Advanced on Mac. Hide status bar and Hide device-only options are enabled by default. The first hides the reading clock and the menu status row while keeping the chapter header. The second hides screen refresh, page animations and frontlight gestures. Turn them off to inspect device-style controls; unavailable hardware functions remain disabled. Each settings option and list action draws its own bottom divider, including the last row in a tab and the choices in the screen-refresh popup. The refresh choices use equal-height rows with edge-to-edge separators and a top rule; adjacent rows share one separator. Hidden options leave no gaps between rows. Remaining controls keep their normal height, with spare space below them. These preferences persist on the Mac and do not change the screenshot fixture.

This build is for renderer testing. It has no Nickel library integration, brightness controls or e-ink refresh. Downloaded dictionaries work on desktop and Android. Vertical text uses the same layout engine as the device builds. See [Building on macOS](development.md#macos).

## Installation

For the first public beta, download `Kobalt-qt5.zip` from the release. To build a firmware 4 package locally, run `python3 tools/build.py --target qt5 --hardware` and use `build/kobalt-qt5/reader-hardware/Kobalt.zip`.

1. Extract the full ZIP on your computer and show hidden files.
2. Copy the complete `.adds` folder from the ZIP to the root of the Kobo drive. Merge folders and replace matching package files. Keep other apps, settings and reading data.
3. Copy the complete `.kobo` folder from the ZIP to the same drive root. Merge folders. It contains `KoboRoot.tgz` for firmware 4 or `Kobo.tgz` for firmware 5 and 6. Do not unpack this archive yourself.
4. Eject the device safely, disconnect USB and let Nickel install the update.

Copy every file supplied in the ZIP, keeping its folder path. Copy `.adds` first so the required resources are present before the update starts. Kobalt creates its support files and `.adds/kobalt/.initialized` installation receipt on first startup. Updates move the older `.adds/.kobalt.initialized` receipt into that folder.

The system package holds only `libkobalt.so`. Fonts, hyphenation dictionaries and the asset manifest go to `.adds/kobalt/assets/`. `manifest.json` names the release version and the size and SHA-256 of each file. If an asset is missing, damaged or belongs to another version, Kobalt keeps its native settings and book-menu reader choice available. Trying to open a book with Kobalt shows a Nickel system dialog titled “Kobalt can't start”. It explains the resource problem, asks you to reinstall Kobalt and shows the installed version. OK returns to the library without opening the book. The event log records `assets-unavailable`. If asset validation fails and the assets folder contains `FSCK0000.000`-style recovery files, the dialog explains that the filesystem may have recovered files under different names. The event log also records `asset-filesystem-recovery`. Kobalt first checks recovery files in the missing asset’s directory. If a file’s size and SHA-256 match the manifest, it renames that file to restore the missing asset and continues validation. It never replaces an existing asset or changes an unmatched recovery file. This restores filenames only; it does not repair the filesystem. An update replaces the managed asset files and keeps settings and saved positions.

Updates from early test builds that used a different plugin name require manual removal of that older plugin and its failsafe copy before installing Kobalt. The current build does not migrate or remove older plugin names.

## Removal and recovery

A normal build stays installed across restarts. To remove it, delete `.adds/kobalt/uninstall` or the whole `.adds/kobalt` folder, then restart Nickel. Removal keeps other files in `.adds/kobalt` unless you deleted the folder. On supported Kobo firmware, an initialized Kobalt watches a confirmed USB session for removal of the `uninstall` marker. After storage remounts and Nickel finishes processing, it shows “Removing Kobalt” and “Restarting your device...” and requests a normal system restart after three seconds. The message lasts ten seconds so it stays visible beyond the restart delay and into shutdown. Restarting does not depend on whether Nickel can display the message. If Kobalt is inactive, restart the device yourself.

A temporary build (`--hardware --temporary`) writes `.adds/kobalt/uninstall-now` before it activates. The next Nickel start removes the library, also after a crash.

Kobalt uses two session markers:

- `startup-session` exists during a synchronous initialization attempt. A crash during that attempt leaves the marker. Waiting for Nickel or a usable screen, or deferring a completed attempt, does not leave it.
- `active-session.json` exists while a book is open or opening. A clean exit, a cancelled opening, a fallback to Nickel, power-off and reboot remove it.

If `startup-session` is present at startup, Kobalt stays inactive and Nickel keeps its reader to prevent a startup crash loop. Read the event log first. Then stop Nickel, delete that marker and start Nickel again to retry Kobalt. A leftover `active-session.json` does not block startup. Kobalt can open a book again after an interrupted reading session or a forced reboot.

NickelHook also parks the library outside `imageformats` for the first three seconds after Nickel starts. A crash in that interval leaves the library parked and inactive. If the restore thread cannot start, the library stays parked for the next startup. Failed initialization restores installed hooks in their original libraries. Install a fresh package to recover. Do not move a parked library back by hand.

To install a new build over a temporary build, copy the new package, then delete `.adds/kobalt/uninstall-now` before you eject. If you leave it, the next start removes the new library.

Kobalt waits for Nickel to finish initialization before creating its reader controller. If Kobalt misses the completion callback, it can recover by checking the existing Power Manager and Nickel's application connection. The check does not create the manager. An unrecognized native layout cannot enable recovery. If native readiness is still unconfirmed after 30 seconds, Kobalt records `startup-failed` and keeps the built-in reader active for that boot.

## Files on user storage

All files are in `.adds/kobalt/`.

| File | Contents |
|---|---|
| `assets/` | Bundled fonts, hyphenation dictionaries and `manifest.json` |
| `config.json` | `enabled`, the Open books in Kobalt choice |
| `reader-settings.json` | Settings that apply to every book: display options, Bionic reading, default font and interface preferences |
| `<hash>.json` | One file per book: saved position, typography, header, footer, clock, orientation, dictionary choice and the Nickel progress baseline |
| `annotations/<key>/` | One folder per book with `bookmarks.json` and `book.json`, see Bookmarks |
| `reopen-layout.json` | Up to 20 layout-check results, keyed by archive digest, at most 8 KiB |
| `.cache/` | Parsed books and their pages, so a book that was opened before opens without parsing. At most 128 MiB; the oldest books are removed first. Kobalt deletes any other file in this folder |
| `events.jsonl`, `events.jsonl.previous` | Event log, two files of at most 128 KiB each |
| `state.json`, `session.json` | Reader state from the last close, sleep or shutdown, and session status. Create `live-state` to write `state.json` on every save instead |
| `startup-session`, `active-session.json` | Recovery markers, see above |
| `uninstall`, `uninstall-now` | Removal control, see above |
| `doc` | Short user instructions |

The event log records startup checks, opening stages, timings, memory and save results. The startup event includes the firmware version and hardware UUID when available. The hardware UUID identifies the model, not an individual device. Startup events also record hook availability, entry and return of Nickel initialization, periodic wait state and book-opening retries. Archive inspection failures include the specific `error_code` in the `native-resource-failed` event with stage `publication-inspection`. It does not record book text, titles, file paths, serials or account data. A position fallback records the name of the chapter file inside the book. `state.json` and `session.json` can contain book identifiers, so keep them private. The log shows the last recorded operation, not a crash stack trace.

## Opening books

The default build opens unencrypted local EPUBs selected through Nickel, regardless of their folder. This includes onboard and SD storage, hidden folders, Kobo's built-in Dropbox and Google Drive downloads, and folders used by third-party sync services. Local files can have any filename or use a symlink; Nickel's EPUB MIME type and Kobalt's archive inspection determine whether they are supported. DRM-free Kobo purchases also open, including extensionless books stored by Nickel. Embedded TrueType and OpenType fonts using standard IDPF font obfuscation are supported. This font embedding method is not DRM. Other resource encryption and unsupported font obfuscation still use Nickel. Book previews, PDFs and protected books use Nickel's reader.

On firmware 4, sideloaded filenames and saved chapter prefixes preserve literal `#`, `?` and percent sequences such as `%20`.

Loading a local book does not require Wi-Fi or an internet connection. On Kobo, Kobalt checks the local loopback interface before opening its resource service. It brings that interface up if needed and preserves its existing IPv4 address. It does not enable Wi-Fi or change other network interfaces.

Nickel stays responsible for authorization. Kobalt receives an opening only after Nickel accepts it, then reads the EPUB's ZIP entries directly. It validates reading sections before displaying the book. Unreadable or unsupported resources cause fallback to Nickel. A store purchase keeps its existing book identity and uses the same progress, completion and sync integration as before. Direct loading does not turn it into a sideloaded book.

Nickel's Reading Settings has a Kobalt section with Open books in Kobalt. It is on after installation. Turning it off sends later openings to Nickel's reader and keeps Kobalt installed. Long-press a book to open it once with the other reader, without changing the setting.

Kobalt supports horizontal Chinese, Japanese and Korean text and Japanese vertical text declared with `writing-mode: vertical-rl`. The `-epub-` and `-webkit-` forms are also supported. A book can alternate vertical and horizontal chapters. Blocks that change writing direction within a chapter start on separate pages. Mixed directions within a paragraph are accepted, but may render sideways, overlap or extend beyond the page. `vertical-lr`, sideways modes and legacy vertical declarations remain unsupported; these books offer the built-in reader. Language alone never selects vertical writing. Use a font with vertical glyphs, such as the bundled Noto Serif CJK.

If Kobalt cannot load an EPUB, it keeps the full-screen Kobalt view and shows a confirmation card titled “Couldn't open this book”. Choose “Try built-in reader” to let Kobo try the original opening request, or “Go back” to cancel. Kobalt checks authorization again before continuing. A book with explicit protection metadata shows a lock and “Opening with Kobo's reader”, then continues automatically after three seconds. During handoff, a temporary copy of the splash covers the library while the native opener runs. The modal Kobalt window closes first, so native messages remain visible. The copy is removed when the native opener returns. Protected routes and accepted “Try built-in reader” choices after a completed content rejection are remembered in memory until Nickel restarts. Authorization, resource-transfer and saved-position failures are not remembered. Reopening an unchanged remembered book shows the handoff screen for three seconds without retrying Kobalt. Changing the book file invalidates its remembered route. “Go back” does not remember a failed opening. An unreadable file alone is not treated as proof of DRM. Previews, PDFs and other unsupported formats open directly in the built-in reader without a Kobalt screen.

While a book is open, Kobalt checks authorization again after sync, a profile update, a volume change and wake. Removal of the book, sign-out, a change of account, subscription closure and loan denial close the book. Closing for authorization saves only the local position.

Closing a book keeps its parsed document in memory. Reopening the same unchanged book is faster, but still goes through Nickel's opening and authorization checks. Opening another book, USB, account changes and restart discard the kept document.

On Kobo, closing a book also saves its parsed document and its pages in `.adds/kobalt/.cache/`. A later opening of the same unchanged book restores them instead of parsing and laying out the book again, also after a restart. Different typography or screen size reuses the parsed document and lays out only the pages. Kobalt still reads one chapter file through Nickel before it opens a cached book, so authorization is checked as for any other opening. A changed book file, a different Kobalt release version, or a different engine version opens without the old cache entry. After a successful cache save, Kobalt removes older cache entries for the same book. Entries for other books remain available. The cache holds at most 128 MiB and removes the oldest books first. With less than 256 MiB free on user storage, books open and close without it. A failed write to the cache leaves that entry unused and does not interrupt reading.

## Reading position and progress

Kobalt saves the position in its own per-book file and writes it back to Nickel when the book opens, when it closes, and when the device sleeps. The first opening imports Nickel's saved position. On later openings, a newer Nickel position wins over the local one. Like Nickel's reader, the write at opening marks the book as the one being read, so Home and the sleep screen show it. Sleep writes Nickel's progress before the device suspends, after saving the local position. Like Nickel's reader, Kobalt opens every saved position: when the exact place is missing, it opens the start of the chapter, and when the chapter is missing, the start of the book. It shows no message, and logs a `native-position-fallback` event with the chapter file.

Kobalt recognizes a changed book by the file size and the ZIP directory, which holds the checksum of every file in the book. When the book changes, for example after an update from the store, Kobalt discards its saved position and typography for that book and imports Nickel's position.

The per-book file also records the CREngine DOM version that wrote the position. Kobalt opens the book with that version again, so a saved position stays valid after an update to CREngine. A new book uses the current version.

On firmware 5 and 6, Nickel stores a chapter path, an element ID and a text offset, so the round trip is exact. On firmware 4, Nickel stores only a chapter path and an element ID. Kobalt gives Nickel the element that contains the position and keeps the exact offset locally.

Kobalt writes Nickel's progress under Nickel's own database lock, through Nickel's own functions, and reads the result back on a separate connection. If the write fails, the local position stays. The write marks the book for normal sync. Kobalt does not claim that the server received it. When a position cannot be mapped to Nickel's format, as in some plain EPUB files, Kobalt records only the time, the reading status and the percentage for a sideloaded plain EPUB. Nickel keeps its own position, and the book is not marked for sync. Other books keep the position locally.

While reading, Kobalt checks Nickel's progress after a sync, an account update, USB and wake, and once a minute otherwise. If a different, newer position arrives, it asks "Keep reading here" or "Go to synced position". It never jumps without asking.

At 90% or more on exit, or when you turn past the last page, Kobalt asks whether to mark the book finished. Like Nickel's reader, opening a finished book marks it as reading again.

## Hardcover progress

Settings → Advanced → Sync reading progress to Hardcover is off until you turn it on. It is available on the firmware 4 and firmware 5/6 builds. When it is on, Kobalt queues an update after a successful native progress save. Kobalt does not turn Wi-Fi on. With no Hardcover token and no NickelHardcover command, it does nothing.

When `/mnt/onboard/.adds/NickelHardcover/config.ini` contains `authorization` or `access_token`, Kobalt calls the [Hardcover GraphQL API](https://docs.hardcover.app/api/guides/gettingbooksprogress/) itself. The token is read from that file and is never written to the log. The call matches [KOReader's Hardcover plugin](https://github.com/Billiam/hardcoverapp.koplugin): `update_user_book_read` on the newest `user_book_read` (highest id), with that read's `edition_id`, its `started_at`, and `progress_pages`. The page count is the queued percent of that edition's page count, the same ratio KOReader uses when a book has no publisher page map. Kobalt has no publisher page map. Hardcover's update input has no percentage field; the site's progress comes from `progress_pages` on that newest read. A book with no read yet gets `insert_user_book_read` on the same fields.

NickelHardcover 0.5.3's command reports success after updating a different row: the unfinished, non-audiobook read with the latest `started_at`. That can be an older read than the one the site shows, and the edition it writes can differ from the user book's edition. A successful command can therefore leave hardcover.app unchanged. Kobalt uses the command only when `config.ini` has no token. The command must be at `/mnt/onboard/.adds/NickelHardcover/cli` (or `CLI`). A linked Hardcover id is passed with the flag that installed command accepts (`--linked-id` on 0.5, `--book-id` on 0.4.2). Kobalt does not pass flags the command does not advertise.

The update is queued when a book opens, when it closes, when the device sleeps, and when it shuts down. Open, close, and sleep use one calculation: the rounded ratio of the current page index to the page count. The queued value is the book's ContentID and that percent. Percents under 2 are not sent. The same percent is not sent twice. An explicit per-book `enabled` value in NickelHardcover's library is honored. The log line `hardcover-note` includes the page index and page count that produced the percent.

Wi-Fi is often already going down at sleep. The command is not waited on, so suspend is not held for the network. A failed or postponed update stays in `.adds/kobalt/hardcover-pending.json` and is tried when Nickel reports that the network connected, or the next time a book is opened or closed. Shutdown stores the update and does not wait for Hardcover.

Kobalt's highlights stay in `.adds/kobalt/annotations/` and are not written to Nickel's bookmark table. Journal sync therefore does not include them. NickelHardcover's own menu, ratings and manual linking stay in Nickel's reader.

Kobalt also reports reading sessions and page turns to Nickel, so Nickel's reading time and last-read date update. On firmware 4, Kobalt accepts either the current reading-session functions or the older pair without a reader-state argument. It requires a complete pair with the same calling convention.

## Reading interface

The Light panel includes an edge-swipe tip below its controls. It explains brightness on the left edge and adds warmth on the right edge only when the device supports adjustable warmth. Layout uses Horizontal margins and Vertical margins; slider labels wrap when needed on smaller screens. Both margin controls use steps of 3 in the unchanged 0 to 120 range, measured at 300 ppi and scaled for the screen.

On Kobo Qt5 and Qt6 builds, the reading menu's status strip shows a Bluetooth icon beside the battery while Bluetooth is powered on. It indicates that Bluetooth is enabled, not that a remote is connected. The icon is hidden while the reading controls are closed. Bluetooth remains controlled by Nickel. Android and desktop do not show this indicator.

Remote page-turn key activity resets Nickel's Bluetooth inactivity timeout while Kobalt is active. Touch page turns do not keep Bluetooth on. Kobalt does not enable Bluetooth or send a periodic heartbeat just because a book is open. When remote activity stops, Nickel retains its normal inactivity shutdown policy.

Kobalt has one interface, in `src/interfaces/reader/`. Its navigation has Exit Kobalt and Settings at the top, and Chapters, Text, Layout, Light, Stats and Search in bottom tabs. Chapters covers the top row with its own Chapters bar and keeps the status strip and the tabs. Each entry shows its number and the page where it starts. The close cell on the bar and the Chapters tab both close the list. Exit Kobalt sits in the same place as the close cell, so it ignores taps until 400 ms after the list has closed. Settings files from older versions can contain `ui_style` and `familiar_navigation`. Kobalt ignores them and keeps them in the file.

The interface is designed for 300 ppi screens, such as the Clara and Libra, and scales to the screen's density, so controls and text have the same physical size on every device. Kobalt reads the density from the device name that the firmware exports in `PRODUCT`, as Kobo's own display plugin does: 212 ppi for the Nia and Aura, 227 for the Elipsa models and 265 for the Aura HD and H2O. For an unknown device it uses the density that Qt reports, and otherwise 300. It logs the result as a `ui-density` event.

While a page turn is running, Kobalt accepts one pending turn. Further turns replace its direction. The current page is painted before the pending turn starts. Opening menus, changing settings, sleeping or leaving the reader discards the pending turn. Opening a book and jumping to a passage do not accept pending turns.

Tap the left third of the page to go back, the right third to go forward and the middle or the title to open the menus. Swipe left or right to turn pages. For books whose EPUB spine declares right-to-left page progression, the left third advances and the right third goes back; horizontal swipes also reverse. Explicit Next and Previous actions, keyboard arrows and hardware page buttons keep their usual meanings. Hardware page buttons follow Nickel's button mapping and its invert setting. Bluetooth remotes and keyboards turn pages with the arrow keys, like Nickel's reader: right and down go forward, left and up go back. Other remote keys, such as page up and down, volume and media keys, do nothing, as in Nickel's reader.

Tap the top-right area of the page, covering the rightmost 33% of its width and 120 pixels in height at 300 ppi, to bookmark the page or to remove its bookmark. A link in that corner still opens. A bookmarked page shows a ribbon at the top: with a header or clock it hangs just left of the chapter progress and runs a little past the strip, and without them it is shorter and stays in the top margin. A page keeps at most one bookmark. When a layout change puts several bookmarks on one page, they become one at the page start with the oldest date. The bookmark icon next to the menu button opens Bookmarks, sorted by page: each row shows the chapter, the page, the page's first words and the date. A row goes to its page. Its remove button asks before it removes. Opening a bottom navigation tab closes Bookmarks and opens that tab. The Text tab shows Aa in the selected reading font, including pending font changes. Opening Bookmarks from Settings, Text or Layout applies the pending changes first. If saving settings fails, the current panel stays open and shows the error.

Bookmarks are Kobalt's own and separate from Nickel's. Each book has a folder in `.adds/kobalt/annotations/`: `kobo-<id>` for purchased books, after Kobo's book ID, and `file-<fingerprint>` for sideloaded books, after the content fingerprint, so a moved or renamed file keeps its bookmarks. `book.json` records the book's path and title. When a sideloaded file changes, its bookmarks come from the most recently saved folder for that path and move to the new folder on the next save. If saved bookmarks cannot be read, Kobalt keeps the file intact and disables bookmark edits until you fix the file and reopen the book. Opening Bookmarks or tapping the bookmark corner shows an error. If a bookmark save fails, Kobalt shows an error and keeps the previous list and ribbon state. This also applies to automatic merges after a layout change and saves that exceed the 1 MiB storage limit.

Non-linear content starts on its own page: spine items marked `linear="no"`, footnote asides and footnote sections. Page turns skip it. A link opens it, and page turns then stay in it until it ends. Page numbers and progress still count its pages. At the last page of the linear text, a forward turn asks whether to mark the book finished.

New books use Libron at 11 pt, 150% line spacing, left alignment, 48 margin units and hyphenation off. Left alignment and justification preserve publisher-centered text, headings and illustrations. Auto keeps all publisher alignment and is the last option in the alignment control. Text size is set in half points from 7 to 20 pt, and margins in units of a 300 ppi pixel from 0 to 120, so both look the same on every screen. Kobalt saves them per book in the screen's pixels. Typography and layout changes show a preview of the current section and apply when the panel closes. Opening Overflow closes the current menu and its dropdowns. A pending Text or Layout draft stays available and applies when Overflow closes. Font, size, extra weight, spacing, alignment, hyphenation and margins are saved per book. Line spacing ranges from 100% to 300% of the font size. Dragging snaps to evenly spaced marks at 100%, 110%, 120%, 130%, 140%, 150%, 175%, 200%, 250% and 300%. The plus and minus buttons change it by one percentage point. Older saved spacing is converted once to preserve its approximate appearance: 122% becomes 150%, other values are squared and divided by 100, rounded to a whole percent and capped at 300%. For a selected variable font with a weight axis, Variable weight selects its designed weight within the font's supported range and reflows the page. Thickness adjusts outlines for every font without changing pagination. Variable fonts show an additional Variable weight slider. The two settings are saved independently and can be used together. Variable weight starts at 450, clamped to the font's supported range. Saved book weights take precedence.

Appearance and viewport changes keep the current page visible for the first second. During rotation, the current page continues painting at the new geometry until reflow finishes, so an empty backing store cannot leave the screen black. After one second, a modal and progress bar appear together. Its single message identifies appearance changes, enabling or disabling bionic reading, or updating page layout after rotation or resizing. The bar reports the engine's current formatting phase. The modal closes when the latest request finishes, fails or is cancelled. Ordinary page turns do not show it.

Header and footer size popovers use the same text size as their controls. The current size has a checkmark on the right. The popover covers the reading panel's border.

Bionic reading is an optional checkbox in Overflow > Display. It emphasizes the first half of each word's letters with the selected family's bold face, with the engine's usual fallback when a bold face is missing. Combining marks stay with their letters. Soft hyphens do not start a new prefix. A word split across inline elements receives emphasis only in its first text fragment. Existing bold text, code, mathematics, ruby, vertical text and scripts that need contextual joining or word segmentation stay unchanged. Prefix emphasis applies to Latin, Greek, Cyrillic and Hebrew, including extended Latin and Cyrillic letters and fullwidth Latin text. The setting applies to every book. Thickness and Variable weight are disabled while Bionic reading is enabled; their stored values return when it is off. Toggling the checkbox keeps the reading position and repaginates the book. Search, selections and links use the original text positions.

Exit waits for a pending appearance preview and its application before saving the reading position. If the preview cannot open, or the engine rejects the change, Exit can still close the book with the last usable appearance. A settings-file write failure keeps the draft open for a retry.

The font picker shows a compact grid above the navigation tabs, with the book still visible above it. The first row has three equal cells: Publisher Fonts, Libron and a Set default font help button. Small uppercase captions show the number of usable embedded font families and the default font. When no embedded fonts are available, Publisher Fonts uses the default font shown in its caption. A checkmark marks the selected reading font. Each page holds twelve choices in three columns, each name in its own face. Font names wrap at word boundaries onto two lines when needed. Names that still exceed the available space use an ellipsis. Font-name previews and the selected-font control follow the current reading weight or Bionic reading mode. Captions and the Aa help icon keep their normal appearance. Use the arrows to browse, select a font to preview it in the book, and choose the X to return to the Text panel. The first page contains only recommended fonts, including Ancizar Serif and Literata. Later pages have separate sections for Nickel's built-in fonts, sideloaded fonts from `/mnt/onboard/fonts`, and supplemental fonts for the book's language. The built-in section contains only TrueType or OpenType fonts that FreeType can read and Nickel exposes. Fonts in Kobo's Qt font format, used by older firmware, are unavailable in Kobalt. Bundled and sideloaded fonts remain available. Display names omit the `NV ` prefix; saved selections keep the original family name. Publisher Fonts keeps the book's own font declarations.

Long press a font to make it the default, then confirm the change. On desktop, right-click or press Shift+F10 for the same dialog. The chosen font stays in its normal grid position, shows Default font below its name and becomes the initial font for new books and the fallback for Publisher Fonts. Existing books keep their selected font. Long press Libron to restore the built-in default. The Aa help button beside Libron uses the current default font inside a circle and always shows instructions when tapped. It does not change the default or the selected reading font.

On Kobo Qt5 and Qt6, plaintext raster images stream from the EPUB ZIP in blocks of at most 64 KiB. Image dimension requests read only the header and send no image body.

CREngine renders supported MathML directly, including stacked fractions. PNG, JPEG, GIF and SVG illustrations render in the book. GIF illustrations are static. Images keep their publisher spacing and CSS dimensions without automatic enlargement. A one-pixel layout boundary retains positive top margins on leading illustrations. Structural CSS selectors such as `:only-of-type` and `:nth-of-type` preserve publisher image spacing and centered text when opening a book or previewing appearance changes. CSS pixel and physical units use the reading screen's density. Font-relative equations scale with the reading text. In dark mode, images marked as equations with `data-tex` or `role="math"` invert neutral ink while preserving coloured parts and transparency. Ordinary illustrations keep their colours.

Code (`pre`, `code`, `kbd`, `samp` and `tt`) uses IBM Plex Mono, also when you choose a reading font. If the reading font has no glyph for a character, Noto Serif supplies it, then Noto Sans Math, Noto Serif CJK, Noto Naskh Arabic and Noto Serif fonts for Hebrew, Armenian, Georgian, Devanagari, Bengali, Tamil and Thai. These fonts cover Greek, Cyrillic, phonetic symbols, mathematics, Chinese, Japanese, Korean, Arabic, Hebrew, Armenian, Georgian, Hindi, Bengali, Tamil and Thai. The picker offers the matching supplemental family for the document language. A supplemental font that is selected or made the default remains available when another language is opened.

Noto Serif CJK uses the book's language and inline `lang` attributes to select regional glyph forms. Text without a recognized CJK language uses Japanese forms. The bundled Regular collection includes Japanese, Korean, Simplified Chinese, Traditional Chinese and Hong Kong Chinese faces. Font coverage does not enable vertical layout.

Chapter lists, chapter headers and single-line interface controls use the bundled Noto fallback fonts for characters missing from the interface font. Kobalt shapes and draws this fallback text with its own font libraries. It loads fallback font bytes when text first needs them and shares the CJK collection between its regional faces. Coverage does not depend on the selected reading font or opening the font picker. CFF and collection fonts also use this path for font-picker samples, instead of the firmware font driver.

Arabic and Hebrew text uses FriBidi for right-to-left ordering and HarfBuzz for letter shaping and mark placement. Paragraphs can mix right-to-left text with Latin words and numbers. Without a publisher or reader alignment override, paragraphs align to the start of their text direction. The bundled Arabic and Hebrew fonts also supply missing glyphs in chapter titles and other interface text. Text direction and EPUB page-turn direction are separate; the spine's page progression still controls taps and swipes.

Thai word selection follows Qt’s Unicode boundaries. It can select a letter cluster rather than a complete dictionary word.

The book's `dc:language` sets the text language, and `lang` attributes set it for parts of the text. The language selects the hyphenation dictionary and the line-breaking rules. CREngine uses libunibreak for Unicode line breaking and its supported CSS `line-break` and `word-break` rules. Kobalt has dictionaries for English (US and UK), German, Dutch, French, Spanish, Italian and Portuguese (Portugal and Brazil). Other languages use CREngine's algorithmic hyphenation. The hyphenation setting still decides whether text is hyphenated.

Pop-ups use the same heading and body text styles. Confirmation buttons use the same height and spacing. Font-section headings have a gray background, and the font panel has the shared thick divider only at its top.

The Light tab is shown only when the host can control the frontlight. Android has no Light tab.

Settings has the following tabs:

- Display: dark mode, Bionic reading, book progress bar, page animations and how often the screen refreshes. Page animations apply only while reading in Kobalt; a handoff to Nickel uses Nickel's own page turns.
- Advanced: smooth images, link indicator, edge swipes for the frontlight, More readable interface text, Sync reading progress to Hardcover on Kobo, and Restore appearance defaults. The Hardcover switch is off until turned on and is shown on firmware 4 and firmware 5/6.
- Dictionaries: browse, install and remove downloaded dictionaries. This tab is available on Android and in the desktop app's Fill window mode.
- Stats: Compact chapter graphs, off by default, and Always show statistics, off by default. With it on, Stats has no tab in the bottom bar. It opens above the tabs whenever the reading controls open. It hides while Settings is open, and while another panel overlaps it, such as Text, Layout, Light or Chapters.
- About: version and Qt build, such as "Version 1.0-beta.1 (Qt5)", the short commit of the sources, with `*` when they had uncommitted changes, the description "An experimental alternative EPUB reader." and acknowledgments.

More readable interface text is on by default. It draws all of Kobalt's own text slightly heavier: menus, panels, Settings, Stats and the header and footer. It does not change the book text, which has its own weight setting. The interface adds 3/256 em to each stroke with the same FreeType emboldening as three steps of the reading weight, and keeps every letter's advance, so no text moves or wraps differently. The change applies at once. The interface uses renamed copies of IBM Plex Sans, IBM Plex Mono and Instrument Serif, called Kobalt UI Sans, Kobalt UI Mono and Kobalt UI Serif, and writes the heavier copies to temporary files outside user storage when it registers the fonts. Search excerpts in the book's font keep their weight.

Text and Layout settings are saved per book, including header and footer sizes, the clock and Kobo orientation. Overflow settings apply to every book. Existing global layout values are used until a book saves its own layout; later global preference saves remove those legacy values. Android continues to follow system rotation.

Page layout has left/right and top/bottom margin sliders. Each slider changes both margins in its pair together. Top and bottom margins add space inside the reading area after the header and footer have reserved their space. Existing books keep their previous vertical insets until changed. Page layout also has header and footer sizes, the reading clock (on by default) and orientation. When the book progress line is shown, the footer text uses the same edge spacing as the header. Automatic rotation is available only on devices with an orientation sensor.

On firmware 4, affected Clara models use NickelRotate’s final touch orientation transform while Kobalt owns rotation. Both landscape orientations use the corrected quarter-turn. Closing or suspending the reader restores native input mapping. Clara 2E and other models retain native mapping. The correction requires both touch driver hooks and the expected portrait panel geometry. Firmware 5 and 6 use Kobo’s Qt6 touch driver, which updates its mapping when the screen orientation changes, including on Clara devices.

Other features:

- Standard Ebooks Kobo link wrappers use their publisher border without a second default underline. Ordinary links retain their default underline. Publisher link colors and decorations remain available.

- A vertical swipe along the left edge changes brightness. On devices with adjustable warmth, a vertical swipe along the right edge changes warmth, and turns off automatic warmth like Nickel's slider does. Each edge zone is 13% of the page width, as in Nickel's reader. Both swipes follow the finger at a constant rate: a third of the page height changes half the light range. Changes round to the nearest whole percentage point, with half steps rounded away from zero in both directions on Qt5 and Qt6. A popover with a two-pixel border on every side shows the percentage and a bulb for brightness or a sun for warmth. The bulb fill follows brightness, with rays added at 30%, 50% and 80%. The warmth rays grow from dots at zero and become thicker at 80%. The popover disappears shortly after release. Cancelling restores the original level. These swipes are unavailable on Android. Settings > Advanced > Swipe along edges to adjust frontlight turns both swipes off; they are on by default. Its description names only the swipes that the device supports. The Light panel changes brightness and warmth through Nickel's own settings. Automatic warmth and its bedtime are set in Nickel; moving the warmth slider turns automatic warmth off, like Nickel's slider does.
- Hold a word for 500 ms to look it up in an installed dictionary. The definition opens in a sheet across the screen, on the half away from the word.
- Dictionary lookup accepts individual Han characters in Chinese and Japanese text. It uses Unicode boundaries, not a Japanese morphological dictionary, so it does not infer compound words.
- Hold a link for 500 ms to open a compact menu with Follow link, Dictionary and Dismiss. A triangle points to the selected passage; the menu does not repeat its text. Taps on links still turn pages or open the reading menu. Follow link opens a footnote in a sheet inside the reading area. Its last row, Show in book, jumps to the note in the book; a small uppercase caption below it names the chapter that holds the note, without a trailing colon or full stop. The reading status strip draws a divider whenever a panel meets its lower edge. A note without a note container continues in the paragraphs after its first one, up to the next element with an ID, a heading or a new section. Other internal links jump after you choose Follow link. Return to passage appears as a footer row only while the reading menu is open. Closing the menu keeps the saved passage. The row shows an undo icon, Return to page followed by the original page number, and a small uppercase caption naming the original chapter. Its close button discards the return position.
- For a web link, Kobalt opens a centered confirmation modal with the full URL and asks whether to open it in the browser. Choose Open to open an HTTP or HTTPS link in Kobo's built-in browser or the Android or desktop browser. Choose Cancel to keep reading. If the browser is unavailable, the URL stays visible and Open is disabled.
- Search uses Nickel's keyboard and returns up to 500 results. It ignores case, and it matches ligatures such as "ﬁ", non-breaking hyphens and zero-width characters as typed. Each result shows its page and chapter, and an excerpt in the font the book is displayed in. With Publisher fonts, the excerpt uses the book's own face when it is a bundled, built-in or sideloaded font, and Libron otherwise.
- Stats shows the current chapter, a chart of every chapter's length from Nickel's word counts, the pages left in the chapter and the book, the book's word count and the minutes read since the book was opened. The word total covers the full book, including text before chapter headings, and counts overlapping file and contents entries only once. If the counts do not cover every reading-order file, the total stays hidden. The chart uses one scale for the whole book, capped at three times the median chapter; a notch marks a capped bar. It shows every chapter on one row and pages only when bars would be narrower than 6 pixels. With Compact chapter graphs turned off, it shows 20 chapters per page. While Nickel counts words, the chart says "Counting words…" and the page figures stay. When Nickel has no word counts, as for plain EPUB files, the chart shows each chapter's length in pages. After at least 5 minutes of reading and 3 forward page turns in the current session, the chapter and book cells show the time left at the session's pace: reading time divided by forward turns. Jumps, backward turns and sleep do not count, and the pace resets when the book is opened again.
- After five minutes, the top menu shows how many whole minutes the book has been open since the last opening. Sleep pauses the count. Closing the book or a USB connection resets it.

Firmware 4 chapter lists use Nickel's own vector accessor. This supports the 32-byte and 48-byte native chapter layouts without assuming a fixed entry stride. If none of Nickel's chapter destinations can be mapped into the book, Chapters uses the EPUB's own table of contents. A partially mapped native list keeps its entries, with unavailable destinations disabled. Native word counts stay unchanged.

NickelBench can select a temporary appearance profile for its dedicated benchmark EPUB. Settings writes are disabled for that opening.

## Display refresh

Kobalt paints one completed frame per page turn. Ordinary turns use Kobo's reading policy for the detected display backend. On firmware 4's i.MX backend, Kobalt queries Nickel's hardware capabilities and the native DisableRegal setting. It uses partial REAGL when Regal is supported and enabled, or partial GLKW16 in dark mode when Eclipse is supported. Other i.MX revisions use driver-selected automatic updates. MediaTek uses full GLR16/GLRC16 or dark GLKW16. Unknown backends keep Kobo's automatic policy. On MediaTek, a page turn that needs image cleanup uses one whole-screen quality refresh. Kobo selects GC16 for greyscale cleanup, GCK16 for dark greyscale cleanup and GCC16 for colour cleanup. Entering dark mode requests one whole-screen cleanup. Closing the menu with a tap on the page or the title requests one full cleanup to clear ghosting. Closing a panel another way, or jumping from Chapters or Search, does not flash. Refresh the screen, on the Display tab, decides which page turns also flash. Smart, the default, flashes on a forward turn onto the first page of a chapter, but only after at least 10 turns since the last flash, so a run of short chapters does not flash on every turn. Every chapter flashes at every chapter start. Every 6, 10 or 20 pages flashes on that many turns since the last flash, in either direction. Manually flashes only when the menu closes. Any flash restarts the count. Each flash logs a `full-flash` event with its reason, and replaces that turn's page animation.

Page animations work on the Clara Colour, Libra Colour and Clara BW, which use MediaTek's `hwtcon` display driver, and follow NickelDissolve's sweep. Animations work in light and dark mode. Text and small greyscale images can use the sweep. A turn onto or away from an image covering at least 10% of the reading image replaces the animation with one whole-screen image-quality refresh. On colour devices, colour regions, including coloured text and backgrounds, also replace the animation with that refresh. Colour alone does not trigger this policy on monochrome devices. Both the outgoing and incoming pages are checked. Kobalt keeps the final page pixels throughout the turn and does not flash image regions separately after a sweep. These are Kobalt's conservative thresholds, not a claim about Nickel's internal thresholds. A failed band or wait requests whole-page cleanup instead of leaving stale bands. Each animated turn logs a `page-animation` event. Animations are off by default. On other devices, including the Elipsa 2E and Tolino models, the option is greyed out. `--no-page-animations` removes them from a build.

Kobalt installs its animation hook when its reader first opens, after startup mods have loaded. It preserves the existing display hook so older NickelDissolve installations keep controlling the built-in reader's animations. The two animation settings are independent. An `animation-hook` event records whether installation succeeded; if it fails, Kobalt leaves its animation setting unavailable. This supports mods loaded at startup. Mods that replace the same hook later without preserving it can still conflict.

Ordinary page turns reuse chapter pages and the available font list in memory. Chapter pages update when the pagination or the chapter list changes. A turn with unchanged appearance and viewport skips appearance validation; rotation can change the viewport without opening Settings. Adjacent page images are prepared after the current page is painted. One retired page buffer can be reused when no session or interface holds its pixels. Resize, appearance changes and image-resource changes discard it. Images discovered on adjacent pages load before those pages are requested.

## Sleep, USB and power

Before sleep, Kobalt saves its position, writes that position to Nickel, and pauses its work. Nickel tells Kobalt it is about to sleep on the interface thread and does not return to the event loop, so Kobalt waits there until the database write finishes. Nickel then builds the sleep screen from the updated percent. The wait is at most two seconds. A queued Hardcover update does not hold suspend. The page stays on screen until Nickel's sleep screen is ready. Kobalt then shows the sleep screen with one full refresh, which also clears the page, so the screen flashes once, as in Nickel's own reader. After wake, Kobalt checks authorization before it shows the book again. If wake or USB cancellation arrives while the previous operation is still releasing resources, Kobalt completes that release before checking authorization again.

A confirmed USB connection closes the book, saves the local position and releases every file on user storage before Nickel exports the storage. Reopen the book from the library afterwards.

Power-off and reboot wait for Kobalt to save reading time and progress before Nickel closes its database. When the application exits, Kobalt stops its engine worker before releasing any remaining cached book models.

## Limits

Kobalt tolerates repeated manifest items when every attribute matches. Conflicting declarations with the same ID remain unsupported.

- ZIP64 archives and `META-INF/encryption.xml` are not supported.
- Resources are limited to 32 MiB each, and the source cache to 32 MiB in total. Images above the limits show a placeholder. An optional image that cannot load shows a warning and does not stop later images from loading. Renewing the source allows another attempt. Cancellation, revoked access and changed resource bytes still stop the session. Interlaced PNG images whose decoded storage exceeds 64 MiB are not rendered, including images embedded inside other resources. The parsed document, fonts and page images are outside the source-cache budget.
- Typography changes lay out the whole book again. There is no partial reflow.
- Hyphenation dictionaries cover only the languages listed above.
- There are no highlights or notes, and no custom tap zones or custom CSS.
- Reading-time estimates use only the current session, and page counts, not words. A font change during a session changes the page count but not the measured pace.

## Hardware validation

Device testing includes installation and reading on Clara Colour, Clara BW with firmware 4.45 and Libra 2 with firmware 4.38. Manual rotation and touch targets were confirmed on Clara BW with firmware 4.45. Page animations with NickelDissolve installed were confirmed on Clara BW with firmware 4.45. Dark-mode refresh quality, sleep with a PIN, rotation on other models and firmware versions, page buttons on Libra Colour and server sync still need hardware validation.

## Android standalone reader

Debug builds appear as Kobalt on the home screen. They use a separate app ID from releases and add `-debug` to the displayed version. Both apps can be installed together. Each keeps its own books, settings and reading progress.

Android uses the shared reader UI and unprotected EPUB pipeline without Nickel. With no book open, the startup screen shows the Kobalt wordmark and “Better reading starts now.” above Choose book and Exit Kobalt buttons. After a successful opening, it also shows a Reopen last book card with the title, author and cover, or a title thumbnail when there is no cover. The card uses the same border and pressed state as the action buttons. Its cover thumbnail is decoded before it is saved. Only the last successfully opened book is saved. A missing or unreadable file hides that card. The screen scrolls on smaller windows. While opening a book, it shows the same loading layout, logo, progress bar and delayed hint as Kobo. The intro screen and its buttons are hidden until opening fails; a successful opening goes directly to the book. Android handles cancellation through system Back. Select a book through the document picker or another app's Open with menu. Imports are copied into app-private storage, with a 128 MiB limit. Reading position, bookmarks and settings stay on the device. Volume Down and Page Down advance on the initial key press; Volume Up and Page Up go back. These keys follow the reading order in both left-to-right and right-to-left books; touch swipes follow the page direction. Holding or releasing a key does not request another turn. Device button remapping can affect when Android delivers these events. Restarting shows the startup screen. Tap Reopen last book to restore its saved reading position. Long-press the card to remove it from recents after confirmation. This keeps the EPUB, reading progress and bookmarks. The reader’s Kobalt button returns to the startup screen. System Back returns there or cancels an opening; Exit Kobalt on the startup screen closes the app. Opening a book through another app still opens that book directly. Protected or invalid EPUBs show an error; Android has no built-in Kobo reader to hand them to. See [Android limitations and setup](../android/README.md).

The Android launcher icon is an outlined open book with Kobalt's serif K and a bookmark. The artwork fills more of the icon while leaving space for the launcher’s adaptive mask.

Android follows the device’s rotation setting on both the startup screen and the reading page. Its Layout menu omits Kobo’s manual rotation controls. Android shows system bars on the startup screen and hides them while reading. The book-opening screen stays visible until the system bars finish hiding and the first page is ready at the final reading size, with its discovered images loaded. On Android, the reader uses the canvas inside the system safe area. Camera cutouts and visible system bars reserve space around the reader. The top status row and bottom navigation stay within that area when the phone rotates or the insets change.

### Downloaded dictionaries

Dictionary downloads are disabled on Kobo, and its settings omit the Dictionaries tab. Kobo lookup uses Nickel's installed dictionaries. The Kobo reader does not start the download manager or use dictionaries previously downloaded through Kobalt.

On desktop and Android, open the Dictionaries tab below Advanced in settings to install and remove downloaded dictionaries from one paged list. Dictionaries for the book's language appear first, followed by other languages. Monolingual dictionaries come before translations. Get starts a download immediately. A circle in the Stop button shows download progress without changing the row height. Section headers have a gray background, and a divider separates the storage footer. Remove asks for confirmation before deleting an installed dictionary. The footer shows space used and available. The catalogue contains the dictionaries from DanielGregorini's [koreader-dicts](https://github.com/DanielGregorini/koreader-dicts) release v1.2.0. Downloading requires an internet connection.

Downloads run in the background and can be cancelled. Kobalt checks the release's SHA-256 digest before installing. Failed or cancelled installs do not become available for lookup. Licenses and attribution stay with the downloaded files on user storage.

The lookup selector uses the same dictionary names and order. Its list overlays the definition without changing the definition layout or page count. The definition pager is hidden while the list is open, so only the selector pager is visible. Kobo entries with multiple parts of speech retain separate headings and definition lists. Lookup first uses an installed dictionary for the book's language, with monolingual dictionaries first, then platform dictionaries, then installed dictionaries for other languages. Choosing another dictionary applies to that book. The choice is saved with the book and restored on reopening. If the dictionary is unavailable, lookup uses automatic selection. Removing the chosen dictionary restores automatic selection. The StarDict reader uses the supplied inflection index and reads compressed definitions as needed. It prefers exact spelling before a case-insensitive match, so an uppercase acronym does not replace a matching lowercase word. Kobo's built-in dictionaries are kept.

Reader confirmations use shared notice and choice modals with a required title, an optional description and an optional image. Dictionary removal and restoring appearance defaults open over the settings sheet. A notice has one action. A choice has two actions. The primary action is filled and the secondary action is outlined. Actions share padding and stack vertically with the primary first when their labels do not fit in one row. Long labels wrap inside the buttons. The font selector points up toward its picker panel.

Chapters, bookmarks, dictionary choices, reading header and footer size choices, and acknowledgments share list rows and caption strips. One, two and three text lines use the same row heights. Current rows are inverted, pressed rows use the existing gray highlight, and long titles end with an ellipsis. Moving a pointer over reader controls does not highlight them. Row press feedback ends on release, including when a list reopens with keyboard focus on that row. Search results keep their book-font excerpts and use the same list spacing and dividers.

### Finding links

Kobalt keeps the book’s link styling. When reading controls are open, pages containing links show a row above the tabs with “Long press a link to see its options.” and a Highlight links button with the link count. Tap the button to reveal the links: each link gets a gray background and an outline. Tap a link to open its options over the page, as a long press does; the reading controls stay closed. Reveal mode hides the normal toolbars so they cannot cover links. A label replaces the header strip, or the footer strip when the header is too small, in that strip’s face and size: “Tap a highlighted link for options” on the left and “Tap elsewhere to exit” on the right. Tap anywhere except a link, the label included, to leave reveal mode. You return to the reading page with the toolbars closed, whether you opened highlight mode from the controls or the link indicator. The dismissal tap does not also open the controls or turn a page. Ordinary reading still uses a long press to open link options.

Advanced settings includes “Show link indicator while reading”. It is off by default. When enabled, pages containing links show a small button with a link icon and the link count at the right of the footer, level with the page number. Without a footer it sits just above the bottom edge. The button opens the same reveal mode. The indicator covers all links, regardless of publisher styling. Revealing links does not change pagination.

Fonts with an optical-size axis show an Optical size slider below Text size. The slider uses whole-point steps and does not change the text size. Fonts use their declared optical-size default, rounded to a whole point. The manual value is saved with the book and restored after reopening. Fonts without this axis hide the row.
